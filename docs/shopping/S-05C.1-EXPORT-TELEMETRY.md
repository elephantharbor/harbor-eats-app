# S-05C.1 — Export telemetry

**Status.** Accepted for the S-05C.1 runtime.

`shop_export` stays on the closed allowlist. The new field is `stage`. Unknown keys are still dropped. A missing `type`, or a `stage` outside the list below, rejects the whole event.

## Stages

| Stage | When | `ok` |
|---|---|---|
| `generated` | The server built a payload (`GET /api/household-shop/export?format=app`). `surface` is `api`. | `true` |
| `attempted` | The person asked to copy or share. | omitted |
| `succeeded` | The clipboard write, the share sheet, the download, or the opened tab completed. | `true` |
| `cancelled` | The person dismissed share, or the request was aborted because the session ended. | `false` |
| `failed` | The copy, the export, or the image could not be prepared. | `false` |

`type` is unchanged: `copy_app`, `image`, `copy`, `share`, `print`, `download`. A download fallback after a share failure is `type: download` and `stage: succeeded`. The earlier share cancel, when there was one, is its own `cancelled` row. It is not a second completion.

## One completed export

`countCompletedShopExports` counts a row with `stage` only when that stage is `succeeded`.

A legacy row has no `stage`. It counts only when `surface` is `shop_sheet` and `ok` is true. The server generation (`surface: api`, no stage) is not a second completion. A new generation row carries `stage: generated`, so it is not a completion either.

## Image exports

Saving or sharing the list image starts as `type: image`, `stage: attempted`.

| Outcome | Completion row |
|---|---|
| The share sheet finishes | `type: image`, `stage: succeeded` |
| The person cancels share | `type: image`, `stage: cancelled`. No completion. |
| Share is unavailable or fails, and the image file downloads | `type: download`, `stage: succeeded`, `surface: shop_sheet` |
| A text or CSV file downloads from the list menu | `type: download`, `stage: succeeded`, `surface: shop_menu` |

The image-file fallback is one completed image export. It is not a second image event, and it is not a text download. `summarizeShopExports` counts it in `image_exports`. `file_downloads` is only `type: download` on another surface, usually `shop_menu`. `by_type.download` still includes the image fallback, so a report that groups by `type` alone will call image saves "downloads" and miss them as images. Use `image_exports` for image handoffs.

One copy therefore stores three rows (a server `generated`, a client `attempted`, and a client `succeeded`), and the completed count is 1. When the list has several parts, each part the person copies is its own attempt and its own success.

Nothing in the event is a list line, a product, a quantity, a note, a member, or a provider account field.

## Client errors that are not export failures

These are expected and are class `expected_abort`. They are not actionable, and the page reporter does not post them.

- `AbortError` from a fetch aborted on sign-out (`apiGet` / `apiPost` / `apiPatch` already returned before reporting; `fetchAppExport` and the export downloads now catch the same error).
- A share the person cancelled (`share_cancelled`, or a message that says the share was cancelled).
- A stored row whose `code` is `aborted`, `aborterror`, `cancelled`, `canceled`, or `share_cancelled`.

`/api/sessions/logout` returning 500 is still actionable if it is reported. The sign-out sheet does not report that HTTP failure itself. It shows “We couldn’t confirm sign-out.” A font timeout is not reported.

Health `client_errors_24h_by_class` includes `expected_abort` and `expected_guard`. The actionable count does not include those rows.

`expected_guard` is an invite guard that worked: code `wrong_household_logged_in`, `invite_expired`, or `invite_inactive`. The classifier reads the stored code, including when the message is `/api/invites/join 409` or empty. The join screen does not file a second report. The general API hook already stored one.

That hook stays quiet when the page is hidden, the page is unloading, or sign-out has started. Safari’s unload abort is a TypeError, `Load failed`, not `AbortError`.

`client_errors_24h_signatures` groups the same 24-hour rows by surface, code, and sanitized message, with `first_seen` and `count`. It has no household id, member id, or page URL. Health is public, so any request-path segment that is not a plain route word (lowercase letters and hyphens) is shown as `:id`, for example `/api/households/:id/members 409`.

Saving the list image catches a failed or aborted list fetch and shows “Couldn’t prepare the image” in the sheet.
